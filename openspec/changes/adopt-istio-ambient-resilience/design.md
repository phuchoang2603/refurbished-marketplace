## Context

See `proposal.md` for motivation and `specs/` for behavior. In `talos-proxmox`, Cilium still supplies pod networking and LB IPAM but its Gateway controller, SPIRE authentication, and Envoy/L7 proxy are disabled. Istio 1.30.5 installs base, istiod, CNI, and ztunnel without enrolling application namespaces. The platform installs Gateway API 1.5.1 **Standard** CRDs, which do not admit `HTTPRoute.rules[].retry`. Marketplace currently renders a `cilium` Gateway, three Cilium policy templates, and stale post-Istio specs. Checkout now atomically stores an intent and outbox command and returns the same checkout for the same buyer/key/identical payload; Web reconstructs that payload from mutable cart and product state on each browser POST.

## Goals / Non-Goals

**Goals:** Keep namespace ownership and mesh policy declarative; ensure mesh entry, database/connector traffic, and browser origins work on a fresh production cluster. Retain dev chart defaults and verify dev/prod manifest renders without a live dev rollout. Use waypoint and ingress Envoy features for bounded resilience, with per-operation retry safety and observable failure behavior. Remove dead pre-saga payment paths and incorrect callback cart mutation.

**Non-Goals:** Replace the Cilium CNI, introduce application retry middleware, reimplement saga reconciliation in the proxy, restore Cilium default-deny policy with new allow-lists, install Istio in this repo, or migrate old cluster/data state. Platform edits stay in `../talos-proxmox` commits, not in this repo.

## Decisions

1. **Single owner for ambient namespaces.** Render `ecommerce` and `kafka` Namespace objects with `istio.io/dataplane-mode: ambient` from the marketplace app-of-apps root, before the child Applications. Existing child charts continue to target those namespaces but do not render or relabel them. Render namespace-scoped `PeerAuthentication` with `STRICT` for both, and validate operator reconciliation, kubelet probes, Strimzi clients, Kafka Connect → Mongo, CNPG, and external ingress during production acceptance. Keep Kafka broker TLS configuration; ambient mTLS is transport protection, not a Kafka replacement. Do not silently use `PERMISSIVE` to paper over a broken path. No namespace-wide waypoint on Kafka, Mongo, Meilisearch, or databases.

2. **Istio owns the browser origin.** Change the marketplace Gateway class to `istio`; retain the existing hostnames, HTTPRoutes, HTTPS forwarding headers, and Cloudflare-managed DNS. Istio auto-provisions the gateway Service as `ecommerce-ingress-istio` for `Gateway/ecommerce-ingress`; make the tunnel binding target that Service and use `http://ecommerce-ingress-istio.ecommerce.svc.cluster.local:80` as the in-cluster origin. If the default Service consumes a Cilium L2 address unnecessarily, configure the generated Service as ClusterIP through Istio Gateway infrastructure parameters; verify the rendered resource rather than relying on the current Cilium Service name. No marketplace TLS Secret is required for the Cloudflare HTTP origin.

3. **Route L7 traffic deliberately.** Render a service-scoped `istio-waypoint` Gateway in `ecommerce`, labeled to handle Service traffic. Label only selected HTTP/gRPC Services `istio.io/use-waypoint` so their east-west calls reach it; Kafka and data stores remain ztunnel-only. Istio ingress-to-Service traffic does not automatically traverse the destination waypoint: set `istio.io/ingress-use-waypoint: "true"` only where required and have the platform owner enable `ENABLE_INGRESS_WAYPOINT_ROUTING` on istiod. Verify waypoint attachment and Envoy route/cluster configuration before claiming policies protect ingress. Use `DestinationRule` for service-local connection/request caps and retry budgets; enable outlier ejection only after a Service has multiple available replicas, since ejecting a sole endpoint removes availability. Avoid `VirtualService` at waypoints because its ambient support is Alpha; prefer Gateway API routes.

4. **Make safe retries opt-in.** The platform owner sets `meshConfig.defaultHttpRetryPolicy.attempts: 0` and installs the **Experimental** Gateway API 1.5.1 CRDs before any chart emits `HTTPRoute.rules[].retry`; never install CRDs from the application repo. Istio 1.30.5's Gateway API conversion handles that field. Configure finite attempts, backoff, per-backend and total timeouts for verified safe HTTP reads and, after validating gRPC method routing at the waypoint, exact unary gRPC method paths. `GetCheckout`, other lookups, and an identical `SubmitCheckout` RPC are replay-safe within their deadlines. GEP-1731's HTTPRoute retry does not define retries by gRPC application status: limit gRPC use to verified transport failures, confirm actual Envoy policies, and do not substitute unstable `VirtualService` routing if the test fails. Do not enable HTTP retries on `/cart/checkout`, cart increments, hosted-payment simulator POST, or callback POST; Web can rebuild different snapshots and rotate an intent key on conflict. Never let mesh retry time exceed the caller deadline or confuse saga order/payment deadlines with per-hop failures. Keep application inbox/outbox replay and compensation unchanged.

5. **Separate callback idempotency from Web side effects.** Payment's saga callback path deduplicates repeat outcomes in one transaction; Web's callback currently drains cart lines for SUCCEEDED, FAILED, and EXPIRED before Checkout finalizes the order. Remove that callback-side drain and the unused status helper. Only drain paid merchant lines when the buyer views the PAID order (or the saga-completed paid flow), as the existing order page already does; repeated removals are no-ops. Keep provider-callback ingestion and uncertain/late success reporting, not a second settlement coordinator.

6. **Remove unused pre-saga payment behavior without deleting the saga.** The standalone `CreateHostedPaymentSession` service path has no production caller; its non-Checkout fallback in `ApplyGatewayWebhook` and the automatic pre-Checkout expiry sweep become dead when that path is removed. Delete those paths and their exclusive SQL, tests, unused protobuf request types, and workers after checking call sites; retain `GetHostedPaymentSessionByOrder` and any response types still needed for payment URL building, or replace those response types with a focused local view. Keep Checkout's durable deadlines and Payment's correlated command/results. `ClearCart` and its unused Web client method are additional cleanup candidates after verifying no external consumers; do not couple an unrelated cart API removal to resilience.

7. **Use the existing telemetry boundary.** Application spans and RED metrics still push OTLP to `otel-agent`. Coordinate proxy scrape/discovery for waypoint, ingress, and ztunnel in the platform-owned agent so retry, overflow, and ejection signals can be inspected without adding an application metrics port or Cilium scrape exceptions. Refresh README, deployment/GitOps docs, architecture and diagram sources, config context, and Cilium-specific Go comments; keep gRPC connection warmup/keepalive behavior unless measured evidence says otherwise. Retire the three Cilium capability specs when eventually syncing the new delta specs rather than retaining contradictory requirements.

## Risks / Trade-offs

- [Strict enrollment disrupts operator or non-mesh paths] → Render namespace labels before workloads; verify dev/prod manifests statically, then check connector → Mongo, database operators, Kafka, probes, telemetry, and ingress during fresh production convergence. Resolve any broken path before accepting the rollout; no live dev deployment is required.
- [Platform change is in another repository] → Treat Experimental CRDs, disabled default retries, ingress waypoint flag, and proxy telemetry as explicit platform-owned prerequisites; do not render unsupported retry fields until they are active. They landed as separate `talos-proxmox` commits (Experimental CRDs, Istio mesh config, ambient-enrolled `otel-cluster` scraper) before this chart emitted retry fields.
- [Ingress-to-waypoint routing adds a hop without a policy to enforce] → The ingress Gateway's only backends, `web` and the simulator, are not waypoint-enrolled, and the ingress Envoy already enforces their timeouts and retries. No Service sets `istio.io/ingress-use-waypoint`; the platform flag stays enabled for a future waypoint-enrolled ingress backend.
- [Unintended duplicate writes] → Keep ingress POSTs unretried by proxy, use exact-match retryable RPCs only, verify Checkout accepts duplicate identical requests, and check cart/callback behavior under response loss.
- [Waypoint creates a shared failure point] → Size and replicate the waypoint for the chosen Services, add sensible connection budgets, and validate it under fault/latency tests; avoid aggressive ejection on one-replica Services.
- [Old capability files and diagrams remain misleading after archive] → Remove retired main capability directories during the eventual spec sync/archive and update diagram sources and exported images alongside docs. No legacy compatibility or data migration procedure is needed on recreated clusters.
